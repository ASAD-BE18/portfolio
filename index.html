Selected Work

Document Intelligence

Making Financial-Document Extraction Reliable

Problem: Financial documents like bank and portfolio statements were often extracted incorrectly, with no systematic way to measure how often — and statements covering multiple accounts couldn't be processed at all.

What I did: Built a repeatable way to measure extraction accuracy against real documents, used it to find and fix the root causes of failures, and extended the pipeline to correctly handle multi-account statements and large financial tables.

Outcome: Measured extraction accuracy rose from 60.4% to 73.6%, and a previously unsupported document type became reliably processable.

Azure Document Intelligence Azure OpenAI Python
Technical details
Built a golden-dataset evaluation harness that scores every extracted field and gates pipeline changes in CI; fixed root-cause prompt failures in unit handling, relative-date parsing, and hallucinated fields, adding chain-of-thought extraction guidelines and anti-hallucination guardrails. Separately, since Azure's prebuilt bank-statement model only detects one account per document, built an AI-based page-boundary detector that splits multi-account statements before extraction.
AI Agents · MCP

Deals MCP: Secure Enterprise Data Access for AI Agents

Problem: AI copilots needed real-time access to enterprise deal and CRM data to be useful, but unrestricted database access for an LLM agent is a serious security risk.

What I did: Built a data-access layer, using the Model Context Protocol, that lets AI agents query deal data safely, with per-tenant access boundaries and full activity logging.

Outcome: AI copilots can now answer real business questions against live deal data without compromising security.

MCP Servers FastAPI Azure Key Vault
Technical details
Read-only, schema-validated SQL layer; per-tenant isolation enforced on every tool call; role-based access control restricting sensitive operations to admins; structured audit logging with request-ID propagation; Key Vault-backed API key issuance; rate limiting on API and SQL execution.
RAG · Document Intelligence

Whole-Document Financial Q&A

Problem: Standard retrieval could answer questions about one part of a document, but not ones spanning an entire financial statement — and some figures inside large tables weren't being captured at all.

What I did: Extended the retrieval system to reliably answer whole-document questions, and made sure figures in large tables are preserved accurately instead of being lost during processing.

Outcome: Users get correct answers to document-wide financial questions, and figures in large tables stay accurate and searchable.

Azure AI Search RAG Architecture Azure OpenAI
Technical details
Added a second, document-level retrieval path alongside chunk-based retrieval for questions that require the whole document. Added a numeric-fidelity check that compares every AI-generated table summary against the source numbers and falls back to verbatim text if any number would be lost, on top of Azure AI Search's hybrid (vector + keyword) retrieval.
AI Infrastructure

Self-Hosted LLM Observability Platform

Problem: Running several production AI services without visibility into cost, performance, or behavior — and without routing that data through a third party — made debugging and cost control difficult.

What I did: Maintain our self-hosted LLM observability platform, a fork of the open-source Langfuse. I built the workflow that merges each upstream release, set up keyless deployment pipelines, and migrated the platform onto two private Kubernetes clusters.

Outcome: Every production AI service can now be monitored and debugged in-house, across all environments, under full internal control.

Azure AKS Langfuse GitHub Actions
Technical details
Observability platform built on the open-source Langfuse project, deployed on a private, VNet-isolated AKS cluster; OIDC-federated CI/CD with no long-lived cloud credentials, running on self-hosted runners inside the private network; an automated process to keep pulling upstream security and feature updates without exposing the platform publicly.
Desktop · On-Device AI

Invictus Echo: Privacy-First AI Meeting Assistant

Problem: Wealth advisors needed their client meetings captured and summarised, without meeting audio leaving their laptop.

What I did: Build and release the Windows and macOS desktop apps, a fork of the open-source Meetily: calendar-driven recording prompts, sign-in with the platform account, participant names from Zoom, Microsoft Teams and Google Meet, on-device speaker diarization, and automatic app updates.

Outcome: Transcription and speaker diarization run on the advisor's own laptop, and the summary goes to the matching client record. Meeting audio never leaves the device.

Rust Tauri whisper.cpp
Technical details
Rust and Tauri desktop app built on Meetily (MIT licence); on-device transcription with whisper.cpp; speaker diarization with ONNX Runtime; Next.js front end; FastAPI backend.
